Scope note

The SI analysis panel currently runs 2000–2014. Either file covers it. The 2022 file matters only if firm-level survey data for 2015 onward is added later — and that data does not yet exist in this project.

The two .dta files were diffed on all shared years (1983–2019): maximum absolute difference 0.0. Matching .csv exports carry identical content; the _long.csv variants give one row per isic × year, which merges more easily outside Stata.

02What's in the data

131 rows, one per manufacturing ISIC4 code.

isic4-digit ISIC Rev. 3 / KBLI 2000 manufacturing code (1511–3720)

wpi2000 = 100 for every code by construction; the do-file asserts this and halts if it fails. Stored as double — 111 of 131 codes are bit-exactly 100 and the rest differ in the last bit (max deviation 1.4×10⁻¹⁴, inherited from wpio.dta's own storage). Test it with a tolerance, not ==.

2016 is missing

No BPS IHPB 2016 publication was available. wpi2016 is missing for all 131 codes — held uniform rather than filled for some codes and not others, so the gap never masquerades as an ISIC-specific artefact.

03Using it downstream

Stored at ISIC4, applied at ISIC3.

The deflator is held at 4-digit level but applied at 3-digit, following Narjoko & Hill (2007) and Aswicahyono, Hill & Narjoko (2010), both of whom use 3-digit WPI deflators in the SI/IBS literature. This is the pattern already in 16_energy_intensity.do:

* 1. collapse ISIC4 -> ISIC3 and reshape to a year lookup
use "wpio_extended_2000_2019.dta", clear
gen isic3 = floor(isic / 10)
reshape long wpi, i(isic) j(year)
collapse (mean) wpi, by(isic3 year)
keep if inrange(year, 2000, 2019)
tempfile wpi_lookup
save `wpi_lookup'

* 2. merge onto firm data and deflate
use "si_energy_emissions.dta", clear
merge m:1 isic3 year using `wpi_lookup', keep(master match) nogen

gen double output_real   = output / (wpi / 100)      // 2000 Rp000
gen double ei_gj_real    = total_gj_s1 / output_real
gen double ln_ei_gj_real = ln(ei_gj_real)

This yields 67 ISIC3 groups × 23 years = 1,541 cells, with only 2016 missing. ISIC3 range is 151–372. Non-manufacturing firm-years get wpi = . and therefore output_real = ., dropping out of log-scale intensity outcomes.

Deflate the denominator only

Monetary intensity (expenditure ÷ output) has nominal Rupiah on both sides, so any deflator cancels exactly — do not apply one. Physical intensity (GJ or tCO₂e ÷ output) has a unit-free numerator and does need the deflated denominator.

04Sources and method

Three stages: the original series, a native chain-link, then a splice.

Stage 1 — 1983–2012, unchanged

Taken directly from wpio.dta: WPI indices at 4-digit ISIC, base 2000 = 100, for 131 manufacturing codes. Originally derived from BPS IHPB publications following Imbruno & Ketterer (2018), Journal of Development Economics.

Stage 2 — 2013–2019, native chain-link

Chain-linked off the 2010 anchor using IHPB annual averages on the (2010 = 100) base:

wpi_t = wpi2010 × (IHPB_t / 100)

Where two IHPB sub-sectors jointly represent one ISIC4 group, their arithmetic mean is used — consistent with the original wpio.dta construction, which already assigned a single WPI series to those codes. ISIC 3710 / 3720 (Recycling) have no IHPB sub-sector and are extrapolated from the 2010–2012 CAGR, as in the original pipeline; under 0.5% of firm-years.

05The 2020–2022 splice

Read this before using those three years for anything level-sensitive.

BPS changed two things at once with the 2020 edition:

  1. Rebased the index from (2010 = 100) to (2018 = 100).
  2. Renumbered and redefined the sub-sectors — 50 groups became 57. Only sub-sectors 1–13 keep their meaning; 37 of 50 numbers now refer to a different industry. Eight groups are new: 14, 21, 35, 42, 44, 49, 55, 57.

So those years cannot use the same chain-link. They are brought onto the (2010 = 100) scale by a link factor anchored on December 2019, observable on both bases — published directly in the 2019 edition, and back-solved on the new base from the 2020 edition's Perubahan / Change (%) column, which that edition's own footnote defines as “Persentase perubahan IHPB Januari 2020 terhadap IHPB Desember 2019.”

f_sub = IHPB_Dec2019(2010=100) / IHPB_Dec2019(2018=100)

IHPB_t(2010-equivalent) = IHPB_t(2018=100) × f_sub        t = 2020, 2021, 2022

Results are expressed back in 2010-base sub-sector numbers, which means ihpb_isic4_concordance.csv is reused completely unchanged — no ISIC4 remapping, and no second semantic match layered on the original one. Every link factor is tabulated in the workbook's splice_2020_2022 sheet.

How accurate is it?

The two index definitions do not agree exactly — different baskets and weights. Measured on the 13 sub-sectors whose number means the same industry on both bases, so that no crosswalk error enters:

Divergence of f from its theoretical valueMedianMeanMax
Across the 13 directly comparable sub-sectors 0.91%1.62%5.48%
 This is the floor for any splice between these two series. Better sub-sector matching would not reduce it.
  • Treat 2020–2022 levels as ±a few percent; prefer 2000–2019 wherever levels matter.
  • In a DiD with year fixed effects the splice error is fully absorbed and does not bias the treatment coefficient — year FE remove anything constant within a calendar year.
  • There is no visible seam: the 2019→2020 deflator ratio (median 1.015) is smaller than an ordinary within-regime year (2021→2022, median 1.038), consistent with COVID-year low inflation rather than a splice artefact.
One code affected

2010-base sub 36, “Industri Media Magnetik dan Media Optik”, has no 2018-base counterpart. It is used only as the secondary of the averaged pair for ISIC 3210, so for 2020–2022 that code falls back to its primary (sub 33) alone. All other codes are unaffected; the do-file handles it automatically and logs it.

06Validation

Extraction checked arithmetically; construction re-derived outside Stata.

Extraction

Every IHPB row was checked by recomputing the annual average from its own twelve monthly indices and comparing to the printed Rata2 / Rata-rata value, tolerance 0.05.

BlockRowsVerified
(2010 = 100) — 50 sub-sectors × 6 years300300

The check earned its keep

It caught three real errors in 2018 — sub-sectors 8, 16 and 17 — where the PDF text layer silently dropped the Average token and the parser picked up December instead. Errors of 3–6 index points, invisible to inspection. Those rows were re-read visually and corrected.

Deflator construction

  • 2019 file: 774 / 774 chain-linked values reproduced exactly by independent recomputation.
  • 2022 file: 1,161 / 1,161 values reproduced exactly.
  • CAGR path for ISIC 3710 / 3720 verified; wpi2000 = 100 for all 131 codes.
  • No seam at the 2012→2013 join — median ratio 1.025, ordinary ~2.5% inflation.
  • Downstream ISIC3 collapse yields exactly the expected 67 × n-years cells.

Full Stata run logs are in logs/.

07Known limitations

Ordered by how much they should change what you do.

  1. The concordance rests on semantic matching. BPS publishes no official crosswalk between IHPB sub-sector labels and ISIC codes. Each ISIC4 code was assigned to the sub-sector whose description most closely corresponds in meaning. Inspect ihpb_isic4_concordance.csv — columns isic4_description and notes — to judge individual matches.
  2. The concordance is ISIC Rev. 3 / KBLI 2000. If SI/IBS microdata for 2015+ is added it will be KBLI 2015/2020 coded (ISIC Rev. 4 lineage). Rev. 3 → Rev. 4 is not a clean 1:1 remap in manufacturing. Budget real time here — this is the expensive dependency, not the deflator.
  3. 2020–2022 are spliced, not native. ±a few percent on levels. See §05.
  4. 2016 is missing. Sourcing the BPS IHPB 2016 edition closes it: add 2016 to the YEARS local in the do-file and re-run. A one-line change.
  5. Do not extend past 2022 with this method. First verify whether IHPB (2018 = 100) continued beyond 2022, and whether BPS rebased again or moved to the Producer Price Index (IHPr).

Reproducing from scratch

Requires wpio.dta, not redistributed here — 131 × 31, base 2000 = 100, 1983–2012.

* place wpio.dta in            <root>/data/raw/
* place the two source CSVs in <root>/data/concordance/
global handoff "<root>"
do "<root>/dofiles/15c_extend_wpio_2022.do"

Both do-files derive every path from $handoff and create output/ and logs/ themselves. They assert on base year, concordance coverage and per-year completeness, so a wrong input file fails loudly rather than silently.
