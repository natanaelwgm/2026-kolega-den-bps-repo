d 'FTOOLS': module to provide alternatives to common Stata commands optimized for large datasets
d 
d  ftools consists of a Mata file and several Stata commands: The
d Mata file creates identifiers (factors) from variables by using
d hash functions instead of sorting the data, so it runs in time
d O(N) and not in O(N log N). The Stata commands exploit this to
d avoid sort operations,  at the cost of being slower for small
d datasets (mainly because of the cost involved in moving data from
d Stata to Mata). Implemented commands are fcollapse, fegen group,
d and fsort. Note that most of the capabilities of levels and
d contract are already supported by these commands. Possible
d commands include more egen functions and merge and reshape
d alternatives.

d 'DRDID': module for the estimation of Doubly Robust Difference-in-Difference models
d 
d  DRDID implements Sant'Anna and Zhao (2020) proposed estimators
d for the Average Treatment Effect on the Treated (ATT) in

N csdid.pkg

d 'CSDID': module for the estimation of Difference-in-Difference models with multiple time periods
d 
d  CSDID implements Callaway and Sant'Anna (2020) estimator for DID
d models with multiple time periods. The main idea of CSDID is that
d consistent estimations for ATT's can be obtained by ignoring 2x2
d DID design that compare late treated units with earlier treated
d units. In the presence of heterogeneous and dynamic effects, this
d type of comparison can severely bias the estimation of Treatment
d effects. CSDID at its core uses DRDID for the estimation of all
d 2x2 DID designs to estimate all relevant ATTGT's (Average
d treatment effects of the treated for group G at time T). Post
d estimation commands can be used to obtain important aggregations.
d CSDID can be used with panel data and repeated cross-section. 
d 
d KW: difference in differences
d KW: DID
d KW: event studies

N eventstudyinteract.pkg
D  3 May 2026
U 6
d 'EVENTSTUDYINTERACT': module to implement the interaction weighted estimator for an event study
d 
d   To estimate the dynamic effects of an absorbing treatment,
d researchers often use two-way fixed effects (TWFE) regressions
d that include leads and lags of the treatment (event study
d specification).  Units are categorized into different cohorts
d based on their initial treatment timing.  Sun and Abraham (2020)
d proposes this estimator as an alternative to the TWFE regression
d in the presence of treatment effects heterogeneous across
d cohorts.  Under treatment effects heterogeneity, the TWFE
d regression can result in estimates with uninterpretable weights,
d which can be assessed by the Stata module eventstudyweights. The
d IW estimator is implemented in three steps.  First, estimate the
d interacted regression with reghdfe, where the interactions are
d between relative time indicators and cohort indicators.  Second,
d estimate the cohort shares underlying each relative time.  Third,
d take the weighted average of estimates from the first step, with
d weights set to the estimated cohort shares.
d 
d KW: event study
d KW: interactions
d KW: two-way fixed effects
d 
d Requires: Stata version 13 and avar, ftools and reghdfe from SSC (q.v.)
d 
d Distribution-Date: 20220911
d 
d Author: Liyang Sun, MIT
d Support: email lsun20@@mit.edu
d

d 'BOOTTEST': module to provide fast execution of the wild bootstrap with null imposed
d 
d  boottest is a post-estimation command that offers fast execution
d of the wild bootstrap (Wu 1986) with null imposed, as recommended
d by Cameron, Gelbach, and Miller (2008) for estimates with
d clustered standard errors and few clusters. It also performs the
d “score bootstrap” (Kline and Santos 2012), which adapts the
d wild approach to Maximum Likelihood estimators. Two wrappers,
d waldtest and scoretest, give easy access to the classical Wald
d (1943) and Rao (1948) score/Lagrange multiplier tests. boottest
d works after regress, cnsreg, ivreg, ivregress, ivreg2 and most
d Stata ML-based estimation commands. boottest offers inference
d based on multi-way clustering after many Stata estimation
d commands that do not otherwise support it. When bootstrapping, it
d offers a choice of Rademacher, Mammen (1993), Webb (2014), and
d standard normal weights. boottest requires Stata version 11.2 or
d later and runs fastest in version 13 or later.
d 
d KW: wild bootstrap
d KW: Cameron
d KW: Gelbach
d KW: Miller
d KW: score bootstrap
d KW: Rao LM test
d KW: multi-way clustering
d 
d Requires: Stata version 13
d

d 'ESTOUT': module to make regression tables
d 
d  estout produces a table of regression results from one or
d several models for use with spreadsheets, LaTeX, HTML, or a
d word-processor table. eststo stores a quick copy of the active
d estimation results for later tabulation. esttab is a wrapper for
d estout. It displays a pretty looking publication-style regression
d table without much typing. estadd adds additional results to the
d e()-returns for one or several models previously fitted and
d stored. This package subsumes the previously circulated esto,
d esta, estadd,  and estadd_plus. An earlier version of estout is
d available  as estout1.
d

d 'PRODEST': module for production function estimation based on the control function approach
d 
d  prodest is a new and comprehensive Stata module for production
d function estimation based on the control function approach. It
d includes Olley-Pakes (OP), Levinshon-Petrin (LP), Wooldridge
d (WRDG) and Ackerberg-Caves-Frazer (ACF) estimation techniques,
d plus a brand new methodology (Mollisi-Rovigatti, MR) in order to
d better deal with short panels.  Its basic usage is similar to
d that of existing modules like opreg or levpet, but  adds many
d features to control the optimization procedures and address
d estimation issues - gross output vs. value added, endogenous
d variables, attrition in the data.
d 
d KW: production function
d KW: control function
d KW: Olley-Pakes
d KW: Levinsohn-Petrin
d KW: Wooldridge
d KW: Mollisi-Rovigatti
d 
d Requires: Stata version 10
d

d

d Support: email  gabriele.rovigatti@@gmail.com
d 
d Author:  Vincenzo Mollisi, University of Rome Tor Vergata
d Support: email  vincenzo.mollisi@@gmail.com
d
